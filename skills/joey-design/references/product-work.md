# 演示、界面、网站和游戏

先确认使用者拿到成品后要做的第一件事，再选入口

| 用途 | 先决定 | 做完怎么验 |
| --- | --- | --- |
| PPT | 谁听这场讲解，哪一页需要图，哪一页需要证据 | 用 PowerPoint 打开 PPTX，核对中文换行、标题、图片和备注，试着改一行字 |
| Web / App UIUX | 用户从哪个状态开始，要做什么决定，做错了如何撤销 | 用键盘走一遍，再在手机宽度测试，核对空列表、筛选、刷新恢复和导出内容 |
| 网站 | 访客先看什么，哪条链接能把他带到作品、产品或下一步 | 手机上点进二级页，直接打开它的链接，再返回列表，逐个检查主要入口 |
| 游戏 | 玩家每回合能做什么，何时获胜，输了怎么再来 | 第一关应能直接上手，实际走通最后一关，也走一次失败路线，检查重开和触控 |

## 低 AI 味

从项目现成的东西里取设计线索，摄影工具用底片条选图，航线游戏把剩余步数写成航程
先用真实素材做一屏，再决定字体、间距、色彩和动效
网站用图片和项目名带人往里走，工具界面把空间给操作，游戏把状态变化放在玩家眼前
把截图里每句话单独读一遍，如果“开启全新体验”放在别的产品上也成立，就写清点完能拿到什么，或者删掉
用户给了真实指标再使用数据，样例标明来历，别编客户评价、奖项和下载量
中文成品不用句号，长句拆开，按钮用“导出入选清单”这样的动词和对象

## 换自己的简报

从安装目录的 assets/studies 复制对应 JSON 和它引用的图片到同一目录，在副本上改，使用新项目 id

- **ui / contact-sheet.json**　每张底片提供稳定 id、文件名、标题、系列、alt 和选片备注，状态保存于当前浏览器，导出入选项的 JSON
- **site / stillroom.json**　每个项目提供全景、近景和两段说明，项目 id 决定可直接分享的地址，about 是可选的工作室介绍
- **game / last-ferry.json**　标题画面用自己的图片，地图逐行写，S 出发、B 接乘客、E 到港、# 栈桥、点号是水面，每关 1 至 5 个候船点，budget 为步数，生成时会检验地图有解且步数足够
- **build / fold-deck.json**　使用演示简报格式，生成中英文 PPTX、网页演示和项目页

每条命令都从本地素材生成，ui、site 和 game 各输出一个可离线打开的 index.html

需要做 SaaS 控制台、原生 App 或动作游戏时，沿用上述任务和验收方式，按用户的技术栈实现对应交互，选片台和航线谜题只是这两个类别的起点
